# Ask VanAssist from the homepage

## Purpose

When Ask VanAssist is enabled, the VanAssist homepage presents it as the preferred starting point for travellers who want to describe what they need in ordinary language.

Ask can search across the VanAssist provider directory, places to stay and enabled traveller-facility data. Useful examples include `dump point near Emerald`, `pet-friendly stay near Rockhampton`, `mobile mechanic near me` and `drinking water near Gladstone`.

## Homepage order

The homepage now presents the journeys in this order:

1. **Ask VanAssist** — describe the need in plain language and optionally use the current device location.
2. **Direct shortcuts** — open trusted services, places to stay, fuel and essentials, or browse all help.
3. **Browse directly** — choose a service category and town, suburb or postcode when a structured search is preferred.

The same hierarchy applies on phones. Ask is intentionally shown before the shortcut boxes and structured category/location form, while those direct paths remain available without requiring Ask.

## Location behaviour

A place written in the question takes priority. If no place is included, Ask can request the device's current location. Denying location permission does not block VanAssist; add a place to the question or use the structured Browse directly form instead.

## Trust and limitations

Ask is a discovery layer over VanAssist data, not a general-purpose assistant. Provider, stay and traveller-facility results keep their existing source, verification and distance rules. Confirm important details with the business, operator or relevant authority before travelling.

Structured `/find`, Places to stay, service directories and assistance requests remain available and are not replaced by Ask.
