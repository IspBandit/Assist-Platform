# Requests and saved providers

## Purpose

Review assistance requests that belong to your account, record supported outcomes, and maintain your saved-provider list.

## Intended users

Signed-in customers who have submitted requests or want to return to a provider profile.

## Permissions

Authentication and customer ownership are required for request detail, images and outcomes. Saving a provider changes only the signed-in user's saved list.

## Fields

Request pages show the reference and request information available to the owner. Outcome forms use the fields presented for that request. A saved-provider action identifies the provider being saved or removed.

## Actions

List requests, open an owned request, download an owned request image, submit an outcome where offered, list saved providers, and toggle a provider in the saved list.

## Workflows

Open **Account → Requests**, select a reference, and review its current state. If an outcome form is available, submit it from that request. Save a provider from its supported customer action and review it later under **Saved**.

## Examples

After a completed assistance request, open its outcome page and record the result. This does not give access to any other customer's request.

## Common mistakes

- Sharing private request or image links.
- Assuming a saved provider is booked, assigned or endorsed.
- Using a request reference that belongs to another account.

## Related pages

See **Account and My Garage** for private assets and documents, and the public provider profile for current business information.

## FAQ

**Does saving a provider contact them?** No. It records a personal saved item only.

**Why can I not open a request reference?** It may not belong to the signed-in account.
